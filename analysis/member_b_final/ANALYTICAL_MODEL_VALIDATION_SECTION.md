# Analytical Model Validation Section

## Purpose

This validation section checks whether the analytical model matches the available RTL cycle-count report for the final `rtl_top_four_4x4` design family.

The validation table is generated by `analysis/analytical_model.py`. The corresponding CSV output is `analysis/results/rtl_partition_validation.csv`.

The comparison is not against an independent simulation run. Instead, it is a consistency check against James's RTL report. The goal is to make sure the analytical model uses the same cycle accounting before deriving latency and efficiency metrics.

## RTL Designs Compared

All three designs use 64 total PEs and implement the same `S = 8`, `D = 64` attention tile.

| Design | PE organization | Total PEs |
|---|---:|---:|
| Single 8x8 array | 1 x 8x8 | 64 |
| Four 4x4 arrays | 4 x 4x4 | 64 |
| Sixteen 2x2 arrays | 16 x 2x2 | 64 |

## Cycle Validation Table

| Design | RTL report cycles | Analytical model cycles | Difference |
|---|---:|---:|---:|
| 1 x 8x8 | 458 | 458 | 0.0% |
| 4 x 4x4 | 386 | 386 | 0.0% |
| 16 x 2x2 | 350 | 350 | 0.0% |

## Breakdown Used by the Model

| FSM phase | 1 x 8x8 | 4 x 4x4 | 16 x 2x2 |
|---|---:|---:|---:|
| QK^T tiled matmul | 192 | 128 | 96 |
| Score capture | 1 | 1 | 1 |
| Row-wise softmax | 176 | 176 | 176 |
| AttnV matmul | 24 | 16 | 12 |
| Stream + done | 65 | 65 | 65 |
| **Total** | **458** | **386** | **350** |

At 100 MHz, the corresponding latencies are:

| Design | Cycles | Latency |
|---|---:|---:|
| 1 x 8x8 | 458 | 4.58 us |
| 4 x 4x4 | 386 | 3.86 us |
| 16 x 2x2 | 350 | 3.50 us |

## Interpretation

The model matches the RTL report because it uses the same FSM-level cycle breakdown. The value of the model is that it turns those RTL cycle counts into higher-level tradeoff metrics, such as latency, area-latency product, and energy-style cost.

The main conclusion is that repartitioning the same 64 PEs reduces cycle count:

| Design | Cycle reduction vs 1 x 8x8 | Total area change vs 1 x 8x8 |
|---|---:|---:|
| 4 x 4x4 | 15.7% fewer cycles | 1.7% more total area |
| 16 x 2x2 | 23.6% fewer cycles | 8.1% more total area |

Power changes by less than 0.3% across all three designs, so the key tradeoff is not power. The key tradeoff is cycle reduction versus routing/area overhead.

| Design | Latency at 100 MHz | Normalized cycles x area | Normalized cycles x power |
|---|---:|---:|---:|
| 1 x 8x8 | 4.58 us | 1.211x | 1.308x |
| 4 x 4x4 | 3.86 us | 1.038x | 1.099x |
| 16 x 2x2 | 3.50 us | 1.000x | 1.000x |

## Note on Validation Scope

This table should be described as a model consistency check, not a full independent validation. It verifies that the analytical model correctly reproduces the RTL report's cycle accounting for the available designs. A stronger validation would require separate RTL simulations for additional workloads or matrix sizes.
