# Member B Report Section: Analytical Model and RTL PPA Comparison

## Overview

My contribution is an RTL-side analytical model for interpreting the synthesized systolic-array attention accelerator. The goal is to translate RTL-level cycle count, frequency, power, and area into system-level performance metrics, and to compare different ways of partitioning the same total number of processing elements.

The final RTL report evaluates three designs with 64 total PEs:

| Design | PE organization | Total PEs |
|---|---:|---:|
| Single 8x8 array | 1 x 8x8 | 64 |
| Four 4x4 arrays | 4 x 4x4 | 64 |
| Sixteen 2x2 arrays | 16 x 2x2 | 64 |

This is a better comparison than the earlier array-size sweep because the PE count is fixed. Therefore, the analysis focuses on how repartitioning the same 64 PEs affects cycles, area, power, and efficiency.

## Model Inputs

The model uses the RTL synthesis and cycle-count results from `rtl/rtl_top_four_4x4/report.md`. The tables in this section are generated by `analysis/analytical_model.py`, with CSV outputs saved in `analysis/results/rtl_partition_comparison.csv` and `analysis/results/rtl_partition_validation.csv`.

All three designs use the same workload:

```text
single-head self-attention
sequence length S = 8
head dimension D = 64
NTILES = 8
```

The main hardware inputs are:

| Parameter | Value |
|---|---:|
| Frequency | 100 MHz |
| Data type | INT8 inputs |
| Total PEs | 64 |
| Matmul inner tile K | 8 |
| Softmax latency | 176 cycles |
| Output stream | 64 output cycles + DONE |

## Cycle Model

The analytical model separates each full attention invocation into four major phases:

```text
total_cycles =
    QK^T tiled matmul phase
  + score capture
  + row-wise softmax
  + AttnV matmul and output stream
```

The key change across designs is the matmul compute window. Smaller arrays have shorter wavefront latency per matmul phase, but require more parallel array instances to keep the same total PE count.

| Metric | 1 x 8x8 | 4 x 4x4 | 16 x 2x2 |
|---|---:|---:|---:|
| Matmul compute duration | 22 cycles | 14 cycles | 10 cycles |
| QK^T phase | 192 cycles | 128 cycles | 96 cycles |
| Score capture | 1 cycle | 1 cycle | 1 cycle |
| Softmax | 176 cycles | 176 cycles | 176 cycles |
| AttnV phase | 24 cycles | 16 cycles | 12 cycles |
| Stream + done | 65 cycles | 65 cycles | 65 cycles |
| **Total cycles** | **458** | **386** | **350** |

At 100 MHz, the latency is:

```text
latency = total_cycles / 100 MHz
```

| Design | Total cycles | Latency |
|---|---:|---:|
| 1 x 8x8 | 458 | 4.58 us |
| 4 x 4x4 | 386 | 3.86 us |
| 16 x 2x2 | 350 | 3.50 us |

## PPA Results

The synthesis results show that all three designs have similar power, because the shared register files, FSM, buffers, and softmax unit dominate the design. The main tradeoff is therefore cycle count versus area.

| Metric | 1 x 8x8 | 4 x 4x4 | 16 x 2x2 |
|---|---:|---:|---:|
| Total cell area | 962,640 um^2 | 943,418 um^2 | 972,359 um^2 |
| Total area including nets | 7,920,862 um^2 | 8,055,035 um^2 | 8,559,044 um^2 |
| Total power | 23.0365 mW | 22.9785 mW | 23.0523 mW |
| Total cycles | 458 | 386 | 350 |
| Latency at 100 MHz | 4.58 us | 3.86 us | 3.50 us |

Relative to the single 8x8 design:

| Design | Cycle change | Total area change | Power change |
|---|---:|---:|---:|
| 4 x 4x4 | -15.7% | +1.7% | -0.25% |
| 16 x 2x2 | -23.6% | +8.1% | +0.07% |

## Analytical Efficiency Metrics

To compare the designs, I use two normalized cost metrics:

```text
area-latency cost = total_cycles * total_area
energy cost ~= total_cycles * total_power
```

Since all designs run at the same 100 MHz, cycle count is proportional to latency. Since power is almost constant, `cycles * power` is proportional to energy per attention invocation.

| Design | Cycles x area | Normalized | Cycles x power | Normalized |
|---|---:|---:|---:|---:|
| 1 x 8x8 | 3.628e9 | 1.211x | 10,552 | 1.308x |
| 4 x 4x4 | 3.109e9 | 1.038x | 8,870 | 1.099x |
| 16 x 2x2 | 2.996e9 | 1.000x | 8,068 | 1.000x |

Lower is better for both normalized metrics. The 16 x 2x2 design has the best area-latency and energy-style efficiency because its cycle reduction is large enough to offset the additional routing area.

## Architectural Insights

The model suggests three main insights:

1. Repartitioning the same 64 PEs improves latency.
   Moving from one 8x8 array to four 4x4 arrays reduces cycles by 15.7%, and moving to sixteen 2x2 arrays reduces cycles by 23.6%.

2. Power is not the differentiating factor.
   Total power remains within 0.3% across all three designs because the shared register files, softmax unit, FSM, and buffers dominate the power.

3. Softmax becomes the main bottleneck.
   The softmax phase is fixed at 176 cycles for all three designs. As the matmul phases get faster, softmax becomes a larger fraction of total runtime, so future optimization should focus on softmax pipelining or parallelization.

## Limitations

This analysis is RTL-side only and should not be treated as a strict apples-to-apples GPU runtime comparison.

- The designs process an `S = 8` attention tile, not full large-sequence attention.
- The model does not include DRAM/cache behavior.
- The comparison is between RTL partition choices with fixed 64 PEs.
- GPU baseline results should be discussed separately as a strong reference baseline.

## Summary

The updated analytical model compares three RTL designs with the same 64 total PEs. The single 8x8 array has the lowest total area, but the 16 x 2x2 design has the fewest cycles and the best normalized area-latency and energy-style efficiency. Because power is nearly identical across designs, the main design tradeoff is routing area versus cycle count. The analysis shows that PE partitioning matters, but the unchanged softmax phase is now the dominant bottleneck and is the most important target for future optimization.
